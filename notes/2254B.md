Analysis of Problem 2254B

Idea: It is advantageous for us to remove a character that is located between two groups of identical elements.

For example:
aaabaaa
Here, b is between two blocks. It is advantageous to delete it, because then we can merge the two identical groups into one, and easily compress the string down to size 1.

Key point!!! The size of a block does not matter, because no matter how long it is, its size will always be 1 after compression.

Therefore, the algorithm:

Count the number of groups after compression (i.e., compress all blocks of identical elements of size > 1 into a single character).

Iterate over indices from 2 to n - 1 (1-indexed), and if a[i - 1] == a[i + 1], then we have found such a character, regardless of the lengths of those two groups.

If we find that a[i - 1] == a[i + 1], the logic is as follows:
We remove a group consisting of 1 character b and the two groups (the left and right blocks), BUT! We compress them into a single group of size 1.
That means we effectively removed 2 groups, not 3.
Therefore, if a[i - 1] == a[i + 1], the answer is immediately groups - 2, because we can perform this operation once.

If we do not find any i such that a[i - 1] == a[i + 1], then the answer is groups - 1. That is, we simply remove one group consisting of a single character b.

Additional case: there might be no groups of size 1. In that case, this will not change the number of groups, because if we remove one character from a group of length > 1, the group does not disappear; it just becomes shorter.
For example:
aaabb; f(s) would return ab. We cannot remove a group here, so in this case the answer is groups. The number of groups does not change.
Therefore, we additionally check whether there is at least one group of size 1. If yes, then the answer is groups - 1, because we can delete that group.

Time complexity: O(n)
Space complexity: O(n) (can also be done in O(1))
