# Розбір задачі [2258B1](https://codeforces.com/problemset/problem/2258/B1)

## Ідея
Спочатку я намагався просто перебирати числа в діапазоні від $mid - 50$ до $mid + 50$ включно, але це дало $TL$, але потім я трохи подивився розбір і зрозумів що може нам допомогти швидко перебирати ікси

Логіка: якщо ми розріжемо всі моркви на якесь число $x$, нас цікавлять тільки числа які $>= x$, тому що ми можемо зробити розріз і отримати числа $х$ та $l-x$, або просто $x$(якщо число $= x$), але ще є один випадок(найвигідніший варіант) бо ми можемо отримати +2 числа, $x$ та $x$, тому ми ще маємо рахувати $freq[2*x]$ тобто кількість таких чисел, чому ми не рахуємо кількість чисел які $>= 2*x$? Тому що коли ми порахуємо, то в ці числа попадуть наприклад $2*х + 1$, $2*х + 2$ і т.д. і вони при розрізі на х не дадуть рівно 2 ікса.

Тобто ми для кожного ікса рахуємо кількість чисел які >= x і додатково freq[2*x] - ті числа які дають ще 2 ікса кожен, але як це рахувати швидко? *Для цього можна використати суфіксний масив*, яким
чином? Ми йдемо з кінця і рахуємо suff[i] = suff[i+1] + freq[i] і що це нам дасть?

Наприклад візьмемо ось такий тест:
4 8
1 8 8 8

Порахуємо freq:
1 0 0 0 0 0 0 3

Тепер suff:
4 3 3 3 3 3 3 3

І що це нам дасть? А те що suff[i](у 1 based індексації) це кількість чисел які >= i
Наприклад suff[5] = 3 і дійсно, є три числа які > 5 це три вісьмірки.
Чому це працює? Все просто, Наприклад коли в нас є 8 чисел від 1 до m включно, коли ми рахуємо suff[7] після suff[8], ми беремо всі числа які дорівнюють 8(і вони всі логічно що більше 7) і беремо suff[7] - всі числа які дорівнюють сіми, тобто це мені нагадує динамичне програмування, тому що ми використовуємо минулі значення для обчислення наступних, наприклад щоб порахувати кількість чисел >= 5(suff[5]), нам треба порахувати суму від suff[5] до suff[m]

Візьмемо ще приклад:
1 7 5 1 7 5 3

Порахуємо freq:
2 0 1 0 2 0 2

Тепер питання, як знайти всі числа які >= наприклад пяти? Тобто suff[5]? Візьмемо suff[7] це всі сімірки, вони більше пяти(і шести) тому кількість елементів > 6 = 2 - дві семірки.

Тепер для suff[5], це всі числа які дорівнюють 7, 6 у цьому випадку і плюс два числа, бо в умові >=, якщо було би просто >, то ми би не додавали freq[i] до suff[i].

Тобто, це суфіксні суми, ця структура допомаає швидко знайти кількість чисел які >= x

Перевіримо на прикладі зверху, побудуємо suff:

7 5 4 4 4 2 2

І дійсно, якщо ми захочемо знайти кількість чисел >= 4, ми просто рахуємо suff[4], це буде 4, перевіримо чи дійсно це так? 
Так, це дійсно так!
$1\ (7)\ (5)\ 1 (7)\ (5)\ 3$
В дужках числа які задовольняють умову

## Тому, алгоритм простий:
1. Порахувати freq
2. Порахувати suff
3. Для кожного x від 1 до m включно перебираємо та рахуємо скільки моркви ми можемо отримати, це буде: suff[x] + freq[2*x]
4. Вивести максимальне значення серед всіх

### За скільки буде працювати цей алгоритм? Порахуємо:
Один прохід для зчитування масиву та підрахунок freq -> $O(n)$

Один прохід для підрахунку suff -> $O(m)$

Та один прохід який проходить по всім можливим 1 <= x <= m за $O(m)$

Вийде: $O(n + 2m) = O(n + m)$

Для $n <= 2*10^5$ та $m <= 2*10^5$ це буде працювати швидко.

## Складність за часом: $O(n + m)$ на один тест.
